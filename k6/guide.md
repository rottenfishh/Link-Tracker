### 🖥️ Нативные "дашборды" в k6?

Если вы запускаете k6 просто из терминала, никаких веб-дашбордов с графиками нет по умолчанию.

Однако есть удобная фича, которая включается флагом: **`--web-dashboard`**.
Если добавить этот флаг при запуске, k6 поднимет локальный веб-сервер и откроет в браузере красивый дашборд в реальном времени.

**Как это выглядит:**
```bash
k6 run --web-dashboard script.js
```
После этого в терминале появится ссылка (обычно `http://127.0.0.1:5665`). Переходите по ней — там будут графики, метрики в реальном времени, таблицы с перцентилями.

Для постоянной работы с графиками и хранением истории тестов обычно используют связку **k6 + InfluxDB + Grafana** . Это когда k6 отправляет результаты в базу данных InfluxDB, а Grafana читает данные из этой БД и рисует красивые дашборды по ID `2587` .

### 📖 Полный гайд по k6

k6 — это современный инструмент нагрузочного тестирования. Скрипты пишутся на JavaScript.

#### 1. Анатомия скрипта и жизненный цикл

Скрипт делится на две принципиально разные части :

*   **Init-код (за пределами `default`):** Выполняется **один раз**.
    *   Сюда пишут: подключение библиотек (`import`), чтение файлов с диска, объявление глобальных констант.
    *   **Важно:** Нельзя делать HTTP-запросы в init-коде, это ошибка.

*   **VU-код (внутри `export default function`):** Выполняется **многократно и параллельно**.
    *   Здесь пишется логика теста: походить по сайту, нажать кнопку, проверить ответ.

```javascript
import http from 'k6/http';   // <-- Init-код (один раз)
import { sleep } from 'k6';

export const options = {       // <-- Конфигурация теста
    vus: 10,
    duration: '30s',
};

export default function () {   // <-- VU-код (крутится в цикле)
    let res = http.get('https://test.k6.io');
    sleep(1);
};

// Опционально: setup и teardown (выполняются один раз ДО и ПОСЛЕ всех VU)
export function setup() { /* Генерация тестовых данных */ }
export function teardown() { /* Очистка */ }
```

#### 2. Главные настройки нагрузки (Options)

Есть два подхода. **Используйте всегда что-то одно**.

**А) Постоянная нагрузка (`constant-vus`)**
Когда вам нужно быстро запустить N пользователей и погонять их M секунд.
```javascript
export const options = {
  vus: 20,
  duration: '5m',
};
```

**Б) Ступенчатая нагрузка (`ramping-vus`) — через `stages`**
Это ваш случай (разогрев 1 минута, стадия 5 минут). Если вы написали `stages`, параметры `vus` и `duration` игнорируются .
```javascript
export const options = {
  stages: [
    { duration: '1m', target: 20 },   // Разогрев до 20 юзеров
    { duration: '5m', target: 20 },   // Держим 20 юзеров 5 минут
    { duration: '10s', target: 0 },   // Сброс (опционально)
  ],
};
```

#### 3. Продвинутые сценарии (Scenarios)

Если в тесте нужно смешать разные типы нагрузки (например, 20 пользователей просто листают страницы, и 5 пользователей в это же время загружают файлы), используйте `scenarios` .

#### 4. Основные операции (API) для проверки бэкенда

*   **GET запрос:** `http.get('url')`
*   **POST запрос с телом:** `http.post('url', JSON.stringify({data: 1}))`
*   **Несколько запросов разом (быстрее):** `http.batch([ ... ])`

#### 5. Проверки (Checks) и Пороги (Thresholds) — для отчета

Это главный механизм, который поможет вам понять, успешно ли прошел тест.

*   **`check` (Проверка):** Валидирует ответ сервера, но **не останавливает** тест при ошибке. Просто считает процент неудач .
    ```javascript
    import { check } from 'k6';
    let res = http.get('url');
    check(res, {
      'Статус 200': (r) => r.status === 200,
      'Время меньше 200ms': (r) => r.timings.duration < 200,
    });
    ```

*   **`thresholds` (Пороги):** Определяют **фейл/пасс** всего теста. Если порог нарушен, k6 завершится с ненулевым кодом ошибки, и CI/CD скажет, что тест провален .
    ```javascript
    export const options = {
      thresholds: {
        http_req_failed: ['rate<0.01'],   // Ошибок < 1%
        http_req_duration: ['p(95)<500'], // 95% запросов быстрее 500 мс
      },
    };
    ```

#### 6. Метрики (Что смотреть в отчете)

k6 сам собирает кучу метрик, которые потом попадают в дашборды или терминал :
*   `http_reqs`: Общее число запросов.
*   `http_req_failed`: Процент неудачных запросов.
*   `http_req_duration`: Длительность запроса (полезно смотреть `avg`, `p(95)`, `p(99)`).
*   `vus`: Текущее количество активных виртуальных пользователей.
*   `iteration_duration`: Время полного круга сценария.
